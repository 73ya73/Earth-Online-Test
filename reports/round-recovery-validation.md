# 上传队列跨会话恢复：本地实施记录

本次基于 a61c30d，仅本地修改和验证，未提交、推送或部署。现有线上网站不会因此改变。此报告中的规则用于取代本地旧文档中“生命周期只尝试三次”的描述；正式生效仍需用户确认后发布 Pages。

## 行为

- 保留 15 秒请求超时、单轮最多 3 次、指数退避及 Retry-After；新增固定 30 分钟轮间冷却，总共最多 3 轮、9 次自动请求。
- 新轮需要重访（页面启动，或 BFCache 恢复）或离线→在线事件。触发时冷却未结束，最多安排一次到期检查；没有新触发，不能只靠时间到期连续开轮。普通可见性变化、跨标签 storage 事件只处理已有待提交请求，不授权下一轮。重复 online 事件也不会反复授权。
- 轮数、本轮次数、累计次数、失败时间、下次允许恢复时间持久化；每次请求前计数。跨标签沿用 Web Locks 和占用租约，并把恢复授权绑定失败轮次，避免旧授权开启后续轮。浏览器不支持 Web Locks 时，仍依赖租约减少竞争和数据库主键防重复。
- 网络、超时、408/429/500/502/503/504 有限重试；权限、参数、记录冲突、数据库确定性拒绝及无效保存确认立即停止，不自动恢复。
- 第九次失败或请求中关闭，完整 payload 仍保留为 failed，不自动删除。清除网站存储或存储不可用仍可能丢失，不能承诺绝对送达。
- 不生成新的 submission_id，跨轮始终发送原 payload。只有匹配编号和 inserted/already_saved 的成功确认才清队列；现有 v2 RPC 已负责验证重算结果及数据库中同编号内容一致性，故本次无需 SQL 或 Edge 改动。
- 旧队列兼容：保持原存储前缀；迁移时记录 queueVersion=3。旧暂时性 failed 视为第一轮结束，从首次迁移时开始冷却，不在每次刷新重新开始计时。旧 sent 凭据和存档处理保持原样。
